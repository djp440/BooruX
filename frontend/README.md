# BooruX 前端

React + TypeScript + Vite 空白脚手架，使用 Bun 管理依赖。

在 `frontend/` 运行：

```sh
bun install
bun run dev
```

打开 Vite 输出的本地地址。入口为 `src/App.tsx`，全局样式为 `src/style.css`。

使用 React Router 的 `BrowserRouter` 和嵌套路由，`Layout` 中唯一的导航通过 `NavLink` 切换页面，`Outlet` 渲染内容。首页 `/` 展示 Danbooru 帖子流，收藏页 `/favorites` 展示默认用户的收藏；两页直接复用 `src/PostFeed.tsx` 的列表、帖子卡片、媒体展示及缓存逻辑，仅数据源和空状态不同。`/settings` 为占位页面，未知路径显示提示。

首页调用 `/api/danbooru/posts?profileId=default`，遵循默认配置的内容分级与数据源。关联父子帖通过 `/api/danbooru/posts/{id}/family` 合并，父帖媒体优先，合并全部成员标签，跨页去重。在线关联查询逐页取完直接子帖；本地模式仅展示已缓存成员并提示可能不完整。

收藏页调用 `/api/profiles/default/bookmarks`，由后端按默认用户的内容分级和标签过滤规则筛选收藏。收藏列表决定展示哪些组，Danbooru 组内沿用首页的整组父子帖媒体合并规则；其他来源的收藏也会保留并按其父子关系合并，使用对应原站名称和链接。首页和收藏使用独立列表缓存，关联媒体缓存共用；收藏页每次进入都会后台检查最新收藏，避免复用 5 分钟内的旧收藏状态。

卡片宽度为内容区减去左右各 8px，最小高度 320px、最大高度 840px；标签区域最多 140px，可独立滚动；媒体区域高度为 `clamp(240px, 50dvh, 560px)`，多媒体横向滑动。使用原始媒体文件地址，画面在容器中等比缩放、不裁切，点击图片可打开原文件；不将缩略图、样本图或转换后的缓存当作原图。视频使用原生播放控件，不自动播放。

提供加载、空列表、错误重试、媒体失败提示和“加载更多”。

帖子底部右侧为收藏、评论、转发图标按钮；评论与转发尚未接入，保持禁用。`src/Bookmarks.tsx` 在路由外共享收藏状态，进入帖子页时检查服务端收藏，操作成功后同步列表和持久缓存。组内任一成员已收藏即显示“已收藏”；新增时收藏可用的父帖（无父帖则收藏当前代表帖），收藏页仍显示整组媒体；取消时通过 `POST /api/posts/{id}/bookmark?profileId=default` 的 `{bookmarked:false,family:true}` 原子移除当前用户该组已有收藏，不影响其他组或其他用户。未带 `family` 的旧接口保留单帖语义。

收藏请求期间禁止重复提交，服务端确认成功后才改变状态；失败保留原状态并显示提示。已收藏按钮使用填充图标、强调色和文字反馈；按压缩放为 160ms CSS transition，键盘操作及减弱动态效果模式不缩放。

帖子列表、已加载的分页游标及父子帖关联结果缓存在浏览器 `localStorage`（`boorux:post-cache:v1`），返回页面和刷新时可恢复。首页 5 分钟内直接复用；之后先展示缓存并后台更新，更新失败保留现有内容；超过 24 小时不再恢复。后台更新成功后用最新首页替换旧列表。缓存最多 40 项、约 2 MiB，超限淘汰旧项，单项过大或存储不可用时降级为页面内存。缓存保存标签和原始媒体地址，不存媒体字节；原图和视频文件沿用浏览器 HTTP 缓存。

宽度达到 768px 时，页面左右各留 15%，可用宽度按导航 25%、内容 75% 分配；导航常驻左侧。移动端导航固定在底部，高度为 51.2px（另加设备底部安全区域），内容无四周内边距，并预留导航高度和设备安全区域，避免遮挡。

API 请求使用 `/api` 相对路径。开发服务器将其代理到 `http://127.0.0.1:48300`；后端需在另一个终端的 `server-go/` 目录运行 `go run .`。

```sh
bun run test    # 帖子分组、去重、原图地址和缓存的定向测试
bun run check   # TypeScript 检查
bun run build   # 检查并构建到 ../server-go/web
```

构建会替换 `server-go/web/` 中的旧页面和资源。构建后重新运行或编译 Go 服务，即可通过 `http://localhost:48300` 访问内嵌页面。
