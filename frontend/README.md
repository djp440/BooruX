# BooruX 前端

React + TypeScript + Vite，使用 Bun 管理依赖。在 `frontend/` 运行：

```sh
bun install
bun run dev
```

开发服务器将 `/api` 代理到 `http://127.0.0.1:48300`；后端在 `server-go/` 运行 `go run .`。入口为 `src/App.tsx`，全局样式为 `src/style.css`。

## 路由与导航

使用 React Router `BrowserRouter`，共享 `Layout` 保留桌面侧栏和移动底部导航：

- `/`：首页帖子列表。
- `/posts/:id`：首页帖子详情。
- `/artists/:name`：作者页，`name` 为 Danbooru 画师标签，列表即该标签的搜索结果；点击帖子卡片的头像或作者名进入（仅限已知的 Danbooru 作者），返回按钮退回来源页并恢复位置。
- `/favorites`：默认用户收藏列表。
- `/favorites/posts/:id`：收藏帖子详情。
- `/chat`、`/chat/:conversationId`：AI 助手（多会话，按需加载）。
- `/settings`：设置页（外观、内容、供应商、数据与存储、关于五个分组）；未知路径显示提示。

两个详情路径都能直达、刷新。顶部吸顶栏标题为“帖子详情”，左侧返回按钮回到进入详情前的列表，保留已加载分页和纵向位置；即使中途切换主导航，仍返回原列表。没有进入记录时回所属列表顶部。浏览器前进后退使用各 history entry 的页面会话。收藏卡片已移除时优先用原后继、前驱恢复位置，再按页面高度夹取滚动。

首页和收藏各自记忆最后停留的列表或详情、纵向位置及已加载评论。导航记忆只在当前标签页生命周期内有效；详情可从持久缓存即时恢复，评论刷新后重新加载。不保存视频进度或媒体横向位置。详情重新进入时先显示已有缓存，同时后台请求服务端校验和更新；网络失败保留缓存并提供重试，服务端返回 401、403 或 404 时清除当前详情缓存与评论并隐藏内容。

## 首页标签搜索

首页列表顶部提供标签搜索框，输入一个或多个 tag，按 Enter 或点击“搜索”提交。多个 tag 用空格分隔并同时匹配，标签本身包含空格时用下划线，例如 `sky blue_hair`。点击“显示全部”清除当前搜索；没有结果时可直接修改条件。搜索通过现有 `/api/danbooru/posts` 的 `tags` 参数查询，加载更多沿用相同标签；本地模式使用现有本地标签查询。

搜索历史保存在当前浏览器 `localStorage`（`boorux:tag-search-history:v1`），最多保留最近 20 条已提交查询，空白规整后去重并前移。历史与语法提示合并在搜索框下拉面板中：聚焦搜索框时展开，输入内容时按子串过滤，方向键 ↓ 进入历史、Esc 收起；点击历史立即重搜并收起面板；点击输入框原生清除按钮（×）等同“显示全部”，退格删空则不触发，“清空历史”移除记录但不改变当前结果；存储不可用时降级为当前页面历史。当前查询、结果分页和滚动位置随首页页面会话保留，从详情返回或切换导航不会重置；刷新首页回到默认查询，历史记录仍保留。搜索结果按完整查询分别缓存，不与默认首页混用分页游标。

## 帖子和收藏

首页调用 `/api/danbooru/posts?profileId=default`。收藏调用 `/api/profiles/default/bookmarks`。列表与详情复用 `src/PostCard.tsx` 的整组媒体、合并标签和收藏操作。Danbooru 列表通过 `/api/danbooru/posts/{id}/family` 合并直接父子帖，在线逐页读取，本地模式提示关联可能不完整。

卡片空白和标签区域点击进入详情，独立“查看详情”按钮提供键盘入口。选中文本、拖动标签、操作视频或媒体轨道不导航；图片继续打开原文件，来源链接和收藏独立操作。评论按钮进入详情并定位评论区，详情内点击仅定位、聚焦评论区；转发继续禁用。没有嵌套交互控件。

列表标签最多四行省略，详情完整展开；媒体按原图比例排布并以 `min(70svh, 680px)` 限高，图片加载前显示微光占位、加载后淡入。多媒体横向滑动吸附，右上角显示位置角标，桌面悬停出现翻页按钮。原始媒体等比缩放、不裁切；不将缩略图、样本或转换缓存冒充原图。视频用原生控件，不自动播放。首次加载显示骨架屏；接近列表底部自动加载下一页，“加载更多”按钮保留为键盘与失败后的入口。收藏成功以底部轻提示反馈，失败在卡片内提示。

`src/Bookmarks.tsx` 在路由外共享收藏状态。组内任一成员已收藏即显示已收藏；新增收藏可用父帖，无父帖则收藏代表帖；取消通过 `POST /api/posts/{id}/bookmark?profileId=default` 的 `{bookmarked:false,family:true}` 原子移除当前用户整组收藏。不影响其他用户或组，不删除帖子、媒体缓存和原始地址；未带 `family` 的旧接口继续保持单帖语义。请求期间禁止重复提交，服务端成功后才更新状态；失败保留原状态。

## 详情与原站评论

`GET /api/posts/{id}/detail?profileId=default` 返回 `success`、`groupId`、`posts`、`source`、`familyComplete` 和 `commentsAvailability`（`available`、`local-only`、`unsupported`）。详情聚合直接父帖和直接子帖，不递归祖先。入口帖被分级或标签规则屏蔽时返回 404；每个可见成员分别过滤，不返回隐藏亲属的关系标识。在线关联失败明确报错。未知来源只读本地已存在帖子。

`GET /api/posts/{id}/comments?profileId=default&memberId=...&cursor=...&limit=25` 读取一个当前可见组成员的原站评论。服务端重新验证成员，不接受任意上游地址。返回 `availability`、`memberId`、`comments`、`nextCursor`、`exhausted`；每条评论保留字符串 `id`、`postId`、`source`、`author`、UTC `createdAt`、文本 `body` 和固定原站 `sourceUrl`。缺省 profile 为 default，显式空值或不存在的 profile 报错。

接入 Danbooru JSON、Safebooru DAPI XML 和 Yande.re JSON。原站分页不能直接当作时间顺序：服务端先有界遍历单帖来源页至末页、去重并按时间排序，再提供成员游标。最多 40 个来源页、单响应 4 MiB，超限、重复页、协议错误或网络错误均返回未完成错误，不静默截断。旧游标所指评论被删除时返回 HTTP 409；前端提供“重新加载评论”，清空整组已展示评论、缓冲、去重记录和游标后从头读取。

前端 `src/comments.ts` 维护各成员缓冲和游标，每次选择全局候选前补齐健康流，保证跨成员、跨页按时间最新优先，同时间固定排序。按来源、单帖和评论 ID 去重。部分成员失败保留成功结果，标明具体可见单帖评论暂缺；普通 502 或网络失败重试沿用原游标，409 则重新加载整组评论。失败状态不能显示“全部加载完成”。补回评论重新归并并尽量保持阅读锚点。

评论展示作者、时间、所属原站单帖及原站链接，正文由 React 转义，保留换行，仅将 HTTP(S) 文本 URL 转为安全外链。作者缺失有兜底文字。不支持发表、回复、完整原站富文本或嵌入媒体。全空、部分失败、全部失败、本地不可用和未知来源分别显示。profile 为 `sqlite` 时在任何原站访问之前短路，评论提示不可用；不会把它显示成“暂无评论”。

## 设置

`/settings` 按五个分组排列，顶部是一排标签页，每次只显示一个分组：外观（背景色）、内容（年龄分级、标签屏蔽）、供应商（AI API 供应商与主模型）、数据与存储（搜索历史、本地帖子缓存）、关于。标签页支持方向键和 Home/End 切换；未保存的草稿保存在页面状态中，切换分组不会丢失。可保存的设置均写入默认用户的 profile 设置，保存与失败提示显示在对应设置项内。

「供应商」分组可保存多个兼容 OpenAI 接口的供应商（名称、API 地址、密钥、Chat Completions / Responses 协议）。添加或修改地址、密钥后会自动请求 `{API 地址}/models` 拉取模型，再从可选列表中加入需要的模型，也可手动输入模型 ID。主模型从所有供应商已加入的模型中选择，可改回「未设置」。已加入的模型和主模型都有「测试」按钮：向模型发送一条短消息（Reply with ok.），并显示耗时和回复内容，失败时显示原因。密钥只写入后端数据库，接口不会回传。

背景色可选 `light`（浅色）、`dark`（暗色）和 `system`（跟随系统，默认）。页面颜色集中为 `style.css` 顶部的语义变量；暗色由 `data-theme="dark"` 启用，跟随系统则移除该标记并由 `prefers-color-scheme` 接管。选择后立即预览，点“保存”写入 `PUT /api/settings?profileId=default` 的 `{themeMode}`；失败恢复原主题，成功后同时缓存到 `boorux:theme`，页面入口在首屏渲染前应用，刷新不闪白。

年龄分级写入同一接口的 `rating`。五档为 `general`（全年龄）、`sensitive`（敏感）、`questionable`（成人）、`explicit`（限制级）与 `all`（全部）；与后端分级值一一对应，未知值分别回退为 `general` 和 `system`。未修改时保存按钮保持禁用。

年龄分级保存成功后立即作废页面内已加载的首页、搜索结果、详情、评论和收藏快照，并清空持久列表缓存；返回首页或收藏时按新分级重新请求，避免旧分级内容继续显示。背景色保存不影响帖子数据。保存失败保留原选中状态并提示重试。

标签屏蔽写入同一接口的 `tagFilter`，结构与后端 `tagfilter.go` 一致：`{blacklistEnabled, blacklist[]}`。白名单等其它字段在保存时原样保留。输入可以一次包含多个以空格分隔的标签，规整规则与后端 `normalizeTag` 一致：去掉 `#`、转小写、空白换成下划线、最长 100 个字符；去重后最多 200 个。后端会过滤首页与搜索列表、详情、关联媒体和收藏。匹配时既比较完整标签，也比较标签按 `_`、`-`、括号等切分后的词，例如屏蔽 `blood` 也会屏蔽 `blood_on_face`。列表过滤在分页游标计算之后执行，单页可能变短，自动加载会继续拉取后续页面。保存成功后与年龄分级一样作废已加载内容。

数据与存储里的“清空搜索历史”和“清除本地帖子缓存”都需要点两次确认，只作用于当前浏览器的 `localStorage`，不影响收藏和服务端数据。

## 缓存与布局

帖子元数据、已加载分页和列表关联结果继续使用 `localStorage`（`boorux:post-cache:v1`），首页和收藏独立，关联媒体缓存共享。首页 5 分钟内复用；之后先展示缓存再后台更新，更新失败保留内容；超过 24 小时不恢复。已有页面会话返回时保留完整分页，不用后台首页替换它。收藏进入时仍后台检查最新状态。最多 40 项、约 2 MiB，超限淘汰旧项；存储不可用降级页面内存。不存媒体字节。详情以 `detail:default:<帖子 ID>` 共用同一帖子缓存，保留服务端返回的组成员和评论可用状态；从列表重新进入、跨首页/收藏进入或刷新时可立即展示，超过 24 小时不从持久缓存恢复。详情每次进入都后台校验，不套用首页的 5 分钟免请求规则；校验期间可能短暂显示上次可见内容，收到不可见响应后移除。详情成员不从旧 family 缓存补入；评论、返回记录和滚动会话均不写入 localStorage 或 sessionStorage。

所有页面共用最宽 600px 的内容列与半透明吸顶页头（首页页头即搜索框）。宽度达到 768px 时为 200px 侧栏（品牌与图标导航）+ 24px 间距 + 内容列，整体最宽 856px 居中。移动导航固定底部，高度 56px 加设备安全区域，内容预留同样高度。

## 验证与构建

```sh
bun run test    # 帖子、缓存、整组评论归并和页面会话定向测试
bun run check  # TypeScript 检查
bun run build  # 检查并构建到 ../server-go/web
```

构建替换 `server-go/web/` 的旧资源。前端构建完成后再运行 Go 定向测试，避免 embed 与资源写入并行；构建后重新编译或启动 Go 服务才会使用新内嵌页面。浏览器中的点击、焦点、桌面/移动布局和异步滚动需要另外实测，纯状态测试不能替代这些验收。

## 媒体查看器

点击帖子图片在当前页面打开全屏查看器（`MediaViewer.tsx`，原生 `<dialog>` + portal），不再跳转新标签页；中键或 Ctrl 点击仍在新标签页打开原图。

- 多媒体帖子可横滑、← / → 键或两侧按钮切换，顶部显示位置计数；视频在查看器中以原生控件播放，切走时自动暂停。
- 点击图片在“适应屏幕”与“原始尺寸”间切换（仅当原图大于显示尺寸），原尺寸以点击处为中心，可滚动或鼠标拖动平移。
- 关闭：× 按钮、Esc（缩放时先退出缩放）、点击图片外空白处，或系统返回手势 / 浏览器后退——打开时压入一条带 `sessionId` 的历史记录，后退只关闭查看器并停留在原列表位置。

## AI 助手

`/chat` 是带工具调用的对话页。后端 agent 每轮最多请求模型 8 次、调用工具 16 次，可用工具有：搜索作品、读取作品、查看收藏、查询标签、收藏/取消收藏；收藏类操作只在用户明确要求时执行。所有工具都受年龄分级和标签屏蔽约束。

- 多会话：点击页头标题展开会话下拉列表，列表限定在内容列内，不占用左侧留白；可切换、重命名、删除会话。再次点击标题、点击外部、按 Esc 或使用后退手势都会收起列表。新对话在发送首条消息时才创建，标题默认取首条消息。不同会话的上下文互相隔离，也可以同时运行。
- 过程反馈：推理过程默认折叠，生成中显示流光；每次工具调用显示为一张卡片，带进行中、完成、失败三种状态，点开可查看参数和结果。作品结果以缩略图网格展示，点击打开媒体查看器，右上角按钮进入详情。正文按 Markdown 渲染（`react-markdown` + `remark-gfm`，不渲染原始 HTML），代码块可以复制。
- 输入：Enter 发送，Shift+Enter 换行，输入法组词时不会误发。图片可以通过按钮、粘贴或拖放添加，每条最多 4 张。模型胶囊用于切换主模型。生成中可以停止，失败或停止后可以重试最后一轮。
- 离开页面时任务在后端继续运行，回来后先读取快照，再按事件游标续接 SSE。未配置供应商时，空状态会引导到 `/settings?tab=settings-providers`。
